Setup guide

Install and configure AnyKanban+

Everything an administrator needs to get a Kanban board running on a record page, from installation to troubleshooting. Allow about fifteen minutes for your first board.

1Before you start

AnyKanban+ is a Lightning Web Component that runs on Lightning record pages. It shows child records of the current record as draggable cards in a Kanban board, grouped by a picklist field you choose.

  • Lightning Experience with permission to edit record pages in Lightning App Builder.
  • A parent object whose record page will host the board, for example Account, Project or Opportunity.
  • One or more child objects that look up to the parent and have at least one picklist field to use as columns, for example Case with Status or Opportunity Product with Stage.

No external services are involved. The component reads and writes records through standard Salesforce APIs, and every query respects object and field-level security.

2Install the package

  1. Open the AnyKanban+ listing on the AppExchange and choose Get It Now. We recommend installing in a sandbox first.
  2. Log in to the target org and choose who the package is installed for. Install for Admins Only is the safest default; you will grant access explicitly in the next step.
  3. Approve the installation. The package adds the AnyKanban+ component, one small custom object (Board Configuration) that stores board settings, the AnyKanban+ Admin permission set and a set of translatable labels.
UpgradingInstalling a newer version over an existing one keeps all saved board configurations.

3Assign permissions

Two groups of people use AnyKanban+ and they need different things.

Administrators who configure boards

  1. Go to Setup, search for Permission Sets and open AnyKanban+ Admin.
  2. Choose Manage Assignments, then Add Assignment, and pick the users who should be able to set up boards.

Only users with this permission set see the gear icon and the Configure Board button on the component. Everyone else sees the finished board.

Everyone who uses the board

End users need no AnyKanban+ permission. They only need their normal access to the objects involved:

  • Read on the child object and on the fields used for the card title and column picklist, so cards appear.
  • Edit on the child object and the picklist field if they should be able to drag cards between columns.
  • Create on the child object if they should be able to use the New button.

If a user lacks access, the related records or buttons are simply hidden for them. The board never bypasses sharing rules or field-level security.

4Add the component to a record page

  1. Open any record of the parent object, click the gear in the header and choose Edit Page.
  2. In the Components panel on the left, scroll to Custom (or search) and drag AnyKanban+ onto the page. A full-width region or the main column works best.
  3. Optionally set Component Height in the properties panel, for example 600px or 80vh. Leave it blank to let the board size itself.
  4. Save, then Activate the page if it is new (as the org default, or for specific apps and profiles).

Back on the record page, the component shows a Configure Board prompt to administrators until a configuration exists.

5Configure the board

Click Configure Board (or the gear icon in the component header) to open the configuration modal. Settings are saved per object: configure the board once on any Account record and it applies to every Account record page in the org.

General

SettingWhat it does
Component TitleThe heading shown in the component. Defaults to AnyKanban+.
Allow DragEnables drag-and-drop to move cards between columns. When off, the board is read-only.
Allow Add RecordsShows the New button and lets users create a record directly into a column.
Allow Edit RecordsAdds an Edit button to the card detail modal.

Child objects

Click Add Child Object and choose a relationship from the list. AnyKanban+ lists every object that looks up to the parent and that you have access to, along with the lookup field used.

SettingWhat it does
Relationship FieldThe lookup on the child object that points to the parent. Pre-filled from the relationship you chose.
Column FieldA picklist field whose values become the Kanban columns. Each picklist value is one column, in the order defined on the field.
Display Name FieldThe field used as the card title, for example Subject or Name.
Card Detail FieldsOptional additional fields shown on each card below the title, for example Owner, Priority or Due Date.
ColourPick a default colour swatch for this object, or turn on Colour by Picklist, choose a second picklist field and assign a colour per value (for example by Priority).
Filter ConditionOptional SOQL WHERE condition without the word WHERE, for example IsClosed = false. Only matching records appear.
Field typesThe Column Field must be a picklist (standard or custom). Multi-select picklists are not supported.

Click Save. The board loads immediately for you, and for every other user the next time they open a record of that object.

To change a configuration later, open the modal again from the same object, adjust the settings and save.

6Using the board

  • Drag a card from one column to another to update the picklist value. The record is saved immediately.
  • Click a card to see its fields. From there, Open Record goes to the full record page and Edit (if allowed) opens an inline edit form.
  • Create records with the New button or by clicking the + at the top of any column. The new record is linked to the parent automatically and the picklist value is set to that column.
  • Column counts show the number of cards in each column. Empty columns still appear so the board layout stays stable.

The board respects each user's Salesforce locale for date and number formats.

7Free edition limit

The Free edition supports one board configuration per org, which means one parent object. You can add as many child objects to that configuration as you like.

When a configuration already exists and an administrator opens the configuration modal on a different object, the modal shows which object is already configured and offers two options:

  • Remove Existing Configuration to free the slot and configure this object instead.
  • Upgrade to Pro for unlimited configurations. Contact us with your org ID (Setup, Company Information) and we will enable it on your org, no reinstall needed.

If an org ever holds more configurations than its limit allows (for example after a downgrade), every board shows a notice until an administrator removes the extra configurations.

8Troubleshooting

What you seeWhat to do
No gear icon or Configure buttonThe user is not assigned the AnyKanban+ Admin permission set. See Assign permissions.
Configuration RequiredNo board has been configured for this object yet. Open the modal and add a child object.
Field was not foundA field used in the configuration was renamed or deleted. Reopen the modal and pick the field again.
Column field must be a picklistThe chosen column field is not a picklist type. Pick a different field.
Field does not look up to this record's object typeThe relationship field points somewhere else. Choose the lookup that targets the parent object.
You don't have accessThe current user lacks Read on the child object or one of its fields. Fix the profile or permission set; AnyKanban+ never widens access on its own.
No cards on the boardUsually a filter or access question. Check the Filter Condition, and confirm matching records exist on this parent.
Board is cut off or too tallSet Component Height on the component in Lightning App Builder.

Still stuck? Send us a message with the object names involved and, if possible, a screenshot of the error. Include your org ID so we can look up your edition.
